# pricing.py: `quote()` Implementation Plan

stats: 1 function | 5 output keys | 3 regions | 2 coupon codes | 3 error messages

## 1. Goal and scope

Build a Python module `pricing.py` that exposes exactly one public function:

```python
quote(cart, region, coupon=None, member=False) -> dict
```

It calculates the price of a shopping cart. All money is **integer cents**, both in and out. Never use floats for money, at any step.

This plan contains every rule. The original requirements are not available to you, so treat this document as the specification.

## 2. Inputs and output

### Inputs

| Parameter | Type | Meaning |
|---|---|---|
| `cart` | `list[dict]` | Line items. May be empty. |
| `region` | `str` | Must be exactly `"US"`, `"EU"` or `"UK"`. |
| `coupon` | `str` or `None` | Optional coupon code. `None` means no coupon. |
| `member` | `bool` | Whether the customer is a member. Defaults to `False`. |

Each cart item is a dict:

| Key | Type | Meaning |
|---|---|---|
| `"sku"` | `str` | Product identifier. Not used in any calculation. |
| `"price"` | `int` | Unit price in cents. |
| `"qty"` | `int` | Quantity. Must be 1 or more. |
| `"category"` | `str` | `"gift-card"` has special treatment. All other values are treated the same. |

### Output

A `dict` with **exactly** these five keys and nothing else. Every value is an `int` (cents):

| Key | Meaning |
|---|---|
| `subtotal` | Sum of `price * qty` over all items, gift cards included |
| `discount` | Coupon discount + member discount |
| `shipping` | Shipping fee |
| `tax` | Tax amount |
| `total` | `subtotal - discount + shipping + tax` |

## 3. Calculation flow

```diagram
title: quote() calculation flow
Caller [user] -> Validate region: cart, region, coupon, member
Validate region -> Raise unsupported region: region not US/EU/UK
Validate region -> Validate qty: region OK
Validate qty -> Raise invalid qty: any item qty < 1
Validate qty -> Empty cart check: all qty OK
Empty cart check -> Return all zeros: cart is empty
Empty cart check -> Subtotal and eligible: cart has items
Subtotal and eligible -> Coupon discount: subtotal, eligible
Coupon discount -> Raise unknown coupon: unrecognised code
Coupon discount -> Member discount: coupon_discount
Member discount -> Shipping: discount = coupon + member
Shipping -> Tax: shipping
Tax -> Total: tax
Total -> Caller [user]: dict of 5 ints
```

## 4. Rules

### 4.1 Validation (runs first, in this order)

Validation happens before **any** calculation, including the empty-cart check.

| # | Check | Condition that fails | Raise (exact) |
|---|---|---|---|
| V1 | Region | `region` not in `{"US", "EU", "UK"}`. The match is exact and case-sensitive, so `"us"` and `" US"` fail. | `ValueError("unsupported region")` |
| V2 | Quantity | Any item has `item["qty"] < 1` (0 or negative) | `ValueError("invalid qty")` |

- V1 is checked before V2. A request with a bad region **and** a bad qty raises `"unsupported region"`.
- V2 scans every item. If any item fails, raise the error. Nothing is calculated before then.
- Do **not** add other validation, such as for missing keys, negative prices or type checks. None is specified.

### 4.2 Empty cart

| Condition | Result |
|---|---|
| Validation passed and `cart == []` | Return `{"subtotal": 0, "discount": 0, "shipping": 0, "tax": 0, "total": 0}` immediately |

> Note: An empty cart returns zeros **before** the coupon is looked at. So `quote([], "US", coupon="BOGUS")` returns all zeros and does **not** raise `"unknown coupon"`. The requirements list only region and qty as up-front validation. See open question OQ-1.

> Note: An empty cart still needs a valid region. `quote([], "CA")` raises `"unsupported region"`.

### 4.3 Subtotal and eligible amount

| Value | Formula |
|---|---|
| `subtotal` | `sum(item["price"] * item["qty"] for all items)`. Gift cards are **included**. |
| `eligible` | Same sum, but only over items whose `category != "gift-card"` |

Gift cards (`category == "gift-card"`, exact string) count toward `subtotal`. They are **never discounted and never taxed**. All discount and tax percentages use `eligible`, not `subtotal`.

### 4.4 Coupon

Normalise the code first: `code = coupon.strip().upper()`. Codes are case-insensitive, and surrounding whitespace is ignored. Skip this whole section when `coupon is None`. In that case `coupon_discount = 0`.

| Normalised code | Condition | `coupon_discount` |
|---|---|---|
| `"SAVE10"` | always | `half_up_pct(eligible, 10)` |
| `"FLAT500"` | `eligible >= 3000` | `500` |
| `"FLAT500"` | `eligible < 3000` | `0`. This is not an error. |
| anything else, including `""` after stripping | — | raise `ValueError("unknown coupon")` |

- `" save10 "`, `"Save10"` and `"SAVE10"` are all valid.
- `"SAVE 10"` (inner space) is unknown.
- FLAT500 can never exceed `eligible`, because it only applies when `eligible >= 3000`.

### 4.5 Member discount

| Condition | `member_discount` |
|---|---|
| `member` is truthy | `half_up_pct(eligible - coupon_discount, 5)` |
| otherwise | `0` |

The member discount is applied **after** the coupon, on what remains of the eligible amount.

Then: `discount = coupon_discount + member_discount`.

### 4.6 Shipping

Evaluate the rows top to bottom. The first match wins.

| # | Condition | `shipping` |
|---|---|---|
| S1 | `member` is truthy | `0` |
| S2 | `subtotal - discount >= 5000` | `0` |
| S3 | region `"US"` | `599` |
| S4 | region `"EU"` | `899` |
| S5 | region `"UK"` | `899` |

> Warning: The free-shipping threshold uses **`subtotal`** (gift cards included), not `eligible`. The comparison is `>=`, so exactly 5000 qualifies.

### 4.7 Tax

| Region | Rate |
|---|---|
| US | 7 % |
| EU | 20 % |
| UK | 20 % |

```
tax_base = eligible - discount + shipping
tax      = half_up_pct(tax_base, rate)
```

- Gift cards are excluded from the tax base, because it starts from `eligible`.
- **Shipping is taxed.** A gift-card-only cart that pays shipping still has tax on the shipping.

### 4.8 Total

```
total = subtotal - discount + shipping + tax
```

### 4.9 Rounding

Every percentage result is rounded **half up** to a whole cent at the moment it is computed. This applies to exactly three values:

| Value | Rounded when |
|---|---|
| SAVE10 discount | right after computing 10 % of `eligible` |
| Member discount | right after computing 5 % of `eligible - coupon_discount` |
| Tax | right after computing the rate × `tax_base` |

Implement this with integer arithmetic only:

```
half_up_pct(amount, percent) = (amount * percent + 50) // 100
```

> Warning: Do **not** use Python's `round()`. It uses banker's rounding, so `round(100.5) == 100`, but half-up must give 101. Do not use floats either. Integer arithmetic is exact.

> Note: All inputs to `half_up_pct` are ≥ 0 when prices are non-negative. The formula rounds half up correctly for non-negative amounts. Negative prices are not specified (see OQ-2).

## 5. Implementation steps

```steps
Module skeleton | Create pricing.py with constants: REGIONS = {"US","EU","UK"}, TAX_PERCENT = {"US":7,"EU":20,"UK":20}, SHIPPING_FEE = {"US":599,"EU":899,"UK":899}, FREE_SHIPPING_THRESHOLD = 5000, FLAT500_MINIMUM = 3000, GIFT_CARD = "gift-card"
Rounding helper | Private _half_up_pct(amount, percent) returning (amount * percent + 50) // 100; integers only, no round(), no floats
Validate region | First statement of quote(): if region not in REGIONS raise ValueError("unsupported region")
Validate qty | Loop all items; if any item["qty"] < 1 raise ValueError("invalid qty")
Empty cart | If not cart, return dict with all five keys = 0
Subtotal and eligible | subtotal over all items; eligible over items whose category != "gift-card"
Coupon | If coupon is not None: normalise with strip().upper(); SAVE10 -> _half_up_pct(eligible,10); FLAT500 -> 500 if eligible >= 3000 else 0; else raise ValueError("unknown coupon")
Member discount | If member: _half_up_pct(eligible - coupon_discount, 5) else 0; discount = coupon_discount + member_discount
Shipping | 0 if member or subtotal - discount >= 5000, else SHIPPING_FEE[region]
Tax | _half_up_pct(eligible - discount + shipping, TAX_PERCENT[region])
Total and return | total = subtotal - discount + shipping + tax; return dict with exactly subtotal, discount, shipping, tax, total
Tests | Add the worked examples and error cases from sections 6 and 7 as unit tests
```

## 6. Worked examples

Every number below was calculated with `half_up_pct(a, p) = (a*p + 50) // 100`.

### Example A: plain US order, no coupon, not a member

Cart: `{"sku":"B1","price":1000,"qty":2,"category":"books"}`

| Step | Calculation | Result |
|---|---|---|
| subtotal | 1000 × 2 | 2000 |
| eligible | no gift cards | 2000 |
| coupon | none | 0 |
| member | not a member | 0 |
| discount | 0 + 0 | 0 |
| shipping | 2000 − 0 = 2000 < 5000, US | 599 |
| tax | (2000 − 0 + 599) = 2599 × 7 % = 181.93 → | 182 |
| total | 2000 − 0 + 599 + 182 | **2781** |

Result: `{"subtotal":2000,"discount":0,"shipping":599,"tax":182,"total":2781}`

### Example B: EU, SAVE10, member, with a gift card

Cart: `{"price":1234,"qty":3,"category":"toys"}`, `{"price":2500,"qty":1,"category":"gift-card"}`

| Step | Calculation | Result |
|---|---|---|
| subtotal | 3702 + 2500 | 6202 |
| eligible | 1234 × 3 | 3702 |
| coupon | SAVE10: 3702 × 10 % = 370.2 → | 370 |
| member | (3702 − 370) = 3332 × 5 % = 166.6 → | 167 |
| discount | 370 + 167 | 537 |
| shipping | member | 0 |
| tax | (3702 − 537 + 0) = 3165 × 20 % | 633 |
| total | 6202 − 537 + 0 + 633 | **6298** |

Result: `{"subtotal":6202,"discount":537,"shipping":0,"tax":633,"total":6298}`

### Example C: half-up matters (UK, SAVE10)

Cart: `{"price":1005,"qty":1,"category":"books"}`

| Step | Calculation | Result |
|---|---|---|
| subtotal / eligible | 1005 | 1005 |
| coupon | 1005 × 10 % = 100.5 → **101** (`round()` would wrongly give 100) | 101 |
| member | not a member | 0 |
| discount | | 101 |
| shipping | 1005 − 101 = 904 < 5000, UK | 899 |
| tax | (1005 − 101 + 899) = 1803 × 20 % = 360.6 → | 361 |
| total | 1005 − 101 + 899 + 361 | **2164** |

Result: `{"subtotal":1005,"discount":101,"shipping":899,"tax":361,"total":2164}`

### Example D: FLAT500 below minimum; gift card unlocks free shipping (US, coupon `" flat500 "`)

| total | 7999 − 0 + 0 + 210 | **8209** |

## 7. Error and edge cases

| Call | Expected |
|---|---|
| `quote([item], "us")` | `ValueError("unsupported region")` (case-sensitive) |
| `quote([item], "CA")` | `ValueError("unsupported region")` |
| `quote([{..."qty":0}], "CA")` | `ValueError("unsupported region")` (region is checked first) |
| `quote([{..."qty":0}], "US")` | `ValueError("invalid qty")` |
| `quote([{..."qty":-2}], "EU")` | `ValueError("invalid qty")` |
| `quote([{..."qty":0}], "US", coupon="BOGUS")` | `ValueError("invalid qty")` (validation runs before the coupon) |
| `quote([item], "US", coupon="SAVE20")` | `ValueError("unknown coupon")` |
| `quote([item], "US", coupon="   ")` | `ValueError("unknown coupon")` (empty after strip) |
| `quote([item], "US", coupon=" save10 ")` | valid, treated as SAVE10 |
| `quote([], "UK")` | all five keys = 0 |
| `quote([], "UK", member=True)` | all five keys = 0 |
| `quote([], "US", coupon="BOGUS")` | all five keys = 0 (see OQ-1) |
| `quote([], "XX")` | `ValueError("unsupported region")` |
