Implementation Plan — pricing.py

Single public function quote(cart, region, coupon=None, member=False) -> dict. This document is the complete specification: every rule, number, error message and edge case needed to build it is here.

1Contract

Signature

quote(cart, region, coupon=None, member=False) -> dict

Located in a module named pricing.py. It is the only required public function.

Inputs

ParameterTypeMeaning
cartlist of dictLine items. May be empty. Each item has exactly the keys below.
regionstrMust be exactly "US", "EU" or "UK" (case-sensitive, no trimming).
couponstr or NoneOptional coupon code. None = no coupon. Case-insensitive, surrounding whitespace ignored.
memberboolWhether the customer is a member. Default False.

Cart item

KeyTypeMeaning
"sku"strProduct identifier. Not used in calculations.
"price"intUnit price in integer cents.
"qty"intQuantity. Must be ≥ 1.
"category"strCategory. The value "gift-card" (exact match) marks a gift card.

Output

A dict with exactly these five keys, every value a Python int in cents (never float, never Decimal):

KeyMeaning
subtotalΣ price × qty over all items, gift cards included.
discountCoupon discount + member discount.
shippingShipping charge.
taxTax charge.
totalsubtotal − discount + shipping + tax

Errors

All errors are ValueError with these exact message strings:

ConditionExceptionWhen checked
region not in {"US","EU","UK"}ValueError("unsupported region")Validation, check #1
Any item has qty < 1ValueError("invalid qty")Validation, check #2
Coupon given and normalized code is not SAVE10 / FLAT500ValueError("unknown coupon")Coupon step (after empty-cart return; see §5)

2Calculation flow

Execute strictly top to bottom. Each percentage is rounded half up at the moment it is computed (orange markers).

3Rule tables

3.1 Validation (runs first, in this order)

#CheckFailureNotes
1region in ("US","EU","UK")ValueError("unsupported region")Exact, case-sensitive. "us", " US", "CA" all fail. Checked even when the cart is empty.
2every item: qty >= 1ValueError("invalid qty")Fails for 0 and any negative value. Region error takes precedence if both are wrong.
3cart is emptynot an errorReturn {"subtotal":0,"discount":0,"shipping":0,"tax":0,"total":0} immediately.

3.2 Amounts

A gift card is identified only by category == "gift-card" (exact string). eligible is internal; it is not returned.

4Rounding

Exactly three values are percentages, and each is rounded half up to a whole cent immediately when computed, before being used in any later step:

ValuePercentRounded before it feeds into…
SAVE10 coupon discount10%member discount base, discount, shipping threshold, tax base
Member discount5%discount, shipping threshold, tax base
Tax7% / 20%total
Do not use Python's round(). It uses banker's rounding (half to even): round(234.5) == 234, round(10.5) == 10. The spec requires 235 and 11. Also avoid floats entirely — 2345 * 0.1 is not exactly 234.5 in binary floating point.

Required helper

Write one private helper, e.g. _pct_half_up(amount: int, percent: int) -> int, using integer arithmetic only. All amounts passed to it are ≥ 0 in this module (see §5), so the formula is:

(amount * percent + 50) // 100

Acceptable alternative: decimal.Decimal with ROUND_HALF_UP, converted back to int. Either way the result must be an int.

5Interpretations & edge cases

The requirements leave a few points implicit. Implement as stated below; items marked confirm should be double-checked with the product manager but must not block implementation.

TopicDecision
Validation orderRegion first, then qty. A call with bad region and bad qty raises "unsupported region". The qty check scans all items before any arithmetic.
Unknown coupon with empty cartThe requirements list only region and qty as "validation", then say an empty cart returns zeros. So an empty cart with an unknown coupon returns all zeros (no error). Coupon is checked only in the coupon step.confirm
Empty / whitespace coupon string"" or " " normalizes to "", which is not a known code → "unknown coupon". Only None means "no coupon".confirm
Region caseNot normalized. Only the exact uppercase strings are valid.
Gift-card-only carteligible = 0 → SAVE10 gives 0, FLAT500 gives 0, member discount 0. Shipping still applies by the normal rule and shipping is still taxed (see Example 9).
Negative amountsCannot occur: SAVE10 ≤ eligible; FLAT500 only when eligible ≥ 3000; member 5% applies to a non-negative remainder. So the tax base and all outputs are ≥ 0 for valid inputs, and the half-up formula for non-negatives is sufficient.
Shipping threshold baseUses subtotal (gift cards included) minus the full discount. Boundary is inclusive: exactly 5000 → free.
Members and shippingMembers always get free shipping regardless of amount or region.
Input mutationDo not modify cart or its item dicts.
Other input validationNot required (types, negative prices, missing keys, unknown categories). Unknown categories are simply non-gift-card items.
Output typePlain dict, exactly the five keys, all int. No extra keys (do not return eligible).

6Implementation steps

Tick steps off as you go (progress is kept in this page only).

  1. Create pricing.py. Define module-level constants:
    • Supported regions: US, EU, UK.
    • Shipping fee per region: US 599, EU 899, UK 899.
    • Tax percent per region: US 7, EU 20, UK 20.
    • Free-shipping threshold 5000; FLAT500 amount 500 and minimum eligible 3000; SAVE10 percent 10; member percent 5; gift-card category "gift-card".
    Keeping region data in one mapping makes the region check and lookups consistent.
  2. Private function taking an int amount and an int percent, returning an int via (amount * percent + 50) // 100. Unit-test it against the table in §4 first, including 2345×10 → 235 and 150×7 → 11.
  3. Signature quote(cart, region, coupon=None, member=False). First statement: if region not in supported set, raise ValueError("unsupported region").
  4. Loop over all items; if any item["qty"] < 1, raise ValueError("invalid qty"). Must run before any arithmetic.
  5. If cart is empty, return the five keys all set to 0. Do not inspect the coupon.
  6. One pass: add price*qty to subtotal for every item; also add to eligible when category != "gift-card".
  7. If coupon is None → 0. Else normalize coupon.strip().upper(); SAVE10 → helper(eligible, 10); FLAT500 → 500 if eligible ≥ 3000 else 0; anything else → raise ValueError("unknown coupon").
  8. If member → helper(eligible − coupon_disc, 5), else 0. discount = coupon_disc + member_disc.
  9. 0 if member or subtotal − discount ≥ 5000; otherwise the region fee (599 / 899 / 899).
  10. helper(eligible − discount + shipping, region_tax_percent).
  11. total = subtotal − discount + shipping + tax. Return dict with keys subtotal, discount, shipping, tax, total.
  12. Write pytest tests for every worked example in §7 and every item in §8. Assert exact dict equality and exact exception messages (pytest.raises(ValueError, match="^unsupported region$") etc.). Assert every returned value is int.
