1. Scope and contract

Create a single module `pricing.py` that exposes one function:

`quote(cart, region, coupon=None, member=False) -> dict`

  • `cart` is a list of item dicts. Each item has `"sku"` (str), `"price"` (int, cents, per unit), `"qty"` (int) and `"category"` (str).
  • `region` is a str. `coupon` is a str or `None`. `member` is a bool.
  • All money is **integer cents**, on input and on output. Never convert to floats or dollars.
  • The return value is a dict with **exactly** these five keys, all of type `int`: `subtotal`, `discount`, `shipping`, `tax`, `total`. Return no extra keys.
  • The function is pure. It must not mutate `cart` or its items, and it does no I/O.
  • Only the three `ValueError` cases listed in section 3 are raised deliberately. Do not add other validation (types, negative prices, missing keys); it is not in scope.

2. Calculation flow

Caller [user] -> Check region: cart, region, coupon, member Check region -> ValueError unsupported region [ext]: region not in US/EU/UK Check region -> Check qty: region ok Check qty -> ValueError invalid qty [ext]: any item qty below 1 Check qty -> Empty cart shortcut: all qty ok Empty cart shortcut -> Return dict [user]: cart empty, all five values 0 Empty cart shortcut -> Subtotal and eligible [svc]: cart not empty Subtotal and eligible [svc] -> Coupon discount [svc]: eligible amount Coupon discount [svc] -> ValueError unknown coupon [ext]: unrecognised code Coupon discount [svc] -> Member discount [svc]: coupon_discount Member discount [svc] -> Shipping [svc]: discount = coupon + member Shipping [svc] -> Tax [svc]: shipping Tax [svc] -> Total [svc]: tax Total [svc] -> Return dict [user]: five int keys Run the stages in exactly this order. Validation (region, then qty) comes before anything else, including the empty-cart shortcut. Each discount stage depends on the previous one, shipping depends on the total discount, and tax depends on shipping.

3. Validation rules

Check these in the order shown. The first failing check raises, and nothing after it runs.

ID | Order | Condition | Result | Notes VAL-1 | 1st | `region` not in {"US", "EU", "UK"} | raise `ValueError("unsupported region")` | Exact, case-sensitive match. "us", " US" and "GB" all fail. Checked even when the cart is empty. VAL-2 | 2nd | any item has `qty < 1` | raise `ValueError("invalid qty")` | Applies to every item, gift cards included. qty 0 and negative qty both fail. VAL-3 | 3rd | `cart` is empty (len 0) | return all five keys = 0 | Only reached when VAL-1 and VAL-2 pass. VAL-4 | in coupon stage | normalised coupon not recognised | raise `ValueError("unknown coupon")` | See section 5 and the open-question callout.

The error messages must match exactly: lowercase, no trailing punctuation, raised as the built-in `ValueError`.

The requirements define validation as the region and qty checks only. They say an empty cart returns zeros right after validation, and that unknown coupon codes raise when coupons are applied. Implement it literally: an empty cart with an unknown coupon returns all zeros and does not raise. Cover this with a test (TC-14) so the behaviour is explicit. If the product manager later wants coupon codes rejected up front, move the coupon check into the validation block after VAL-2.

4. Subtotal and eligible amount

Value | Formula | Includes gift cards? line amount | `price * qty` | n/a subtotal | sum of line amounts over **all** items | yes eligible | sum of line amounts over items whose `category != "gift-card"` | no
  • The gift-card test is an exact string comparison with `"gift-card"`. Other categories need no special handling.
  • Gift cards count toward `subtotal`, which affects both the free-shipping threshold and `total`. They are **never** discounted and **never** taxed.

5. Discount rules

5.1 Coupon normalisation

  • If `coupon is None`, there is no coupon and coupon_discount = 0.
  • Otherwise compute `code = coupon.strip().upper()`. Codes are case-insensitive and surrounding whitespace is ignored.
  • An empty or whitespace-only string is **not** the same as `None`. It normalises to "", which is unknown, so it raises `ValueError("unknown coupon")`.

5.2 Coupon table

Normalised code | Condition | coupon_discount | Rounding SAVE10 | always | 10% of eligible | half up (section 8) FLAT500 | eligible >= 3000 | 500 | none (exact) FLAT500 | eligible < 3000 | 0 (no error) | none anything else | n/a | raise `ValueError("unknown coupon")` | n/a

FLAT500 can never exceed the eligible amount, because it only applies when eligible is at least 3000.

5.3 Member discount

member | member_discount | Rounding True | 5% of (eligible - coupon_discount) | half up, computed after the coupon False | 0 | n/a

`discount = coupon_discount + member_discount`. This combined value is the returned `discount`.

6. Shipping rules

Evaluate the rows top to bottom and use the first one that matches.

Rule | Condition | shipping SHP-1 | member is True | 0 SHP-2 | subtotal - discount >= 5000 | 0 SHP-3 | region == "US" | 599 SHP-4 | region == "EU" or "UK" | 899
  • The threshold uses **subtotal**, so gift cards count toward it. It is inclusive: exactly 5000 qualifies.
  • Shipping is a flat amount per order, not per item.

7. Tax rules

`taxable = eligible - discount + shipping`, and `tax = half_up(taxable * rate)`. Tax is computed once on the whole taxable amount, not per item.

Region | Tax rate US | 7% EU | 20% UK | 20%
  • Shipping is taxed. Gift cards are not taxed, because they are excluded from eligible.
  • Edge case: for a cart with only gift cards, eligible is 0. If shipping is charged, tax is still due on the shipping (see EX-8). This follows the formula literally and is intended.

8. Rounding

Python's built-in `round()` uses banker's rounding: `round(100.5) == 100`. The requirement is round half up, so 100.5 must become 101. Float arithmetic can also misrepresent values such as x.5. Use integer arithmetic only.
  • Write a private helper, for example `_pct(amount, percent)`, that returns `(amount * percent + 50) // 100`. Here `amount` is a non-negative int in cents and `percent` is an int (10, 5, 7, 20). This gives half-up rounding for non-negative values.
  • Use it for exactly three values: the SAVE10 discount, the member discount and the tax. Round each one **at the moment it is computed**, and use the rounded result in later steps. Never carry unrounded fractions forward.
  • Subtotal, eligible, FLAT500 and shipping are already exact integers and need no rounding.
  • The helper assumes non-negative inputs. That always holds for non-negative prices, which is the expected input domain.

9. Total and output

`total = subtotal - discount + shipping + tax`

Return `{"subtotal": ..., "discount": ..., "shipping": ..., "tax": ..., "total": ...}` with every value an `int`.

10. Implementation steps

Module constants | Define REGIONS = {"US","EU","UK"}, SHIPPING_FEE = {"US":599,"EU":899,"UK":899}, TAX_PERCENT = {"US":7,"EU":20,"UK":20}, FREE_SHIPPING_THRESHOLD = 5000, FLAT500_MIN = 3000, FLAT500_AMOUNT = 500, SAVE10_PERCENT = 10, MEMBER_PERCENT = 5, GIFT_CARD = "gift-card" Rounding helper | Add _pct(amount, percent) returning (amount * percent + 50) // 100; integer only Validate region | If region not in REGIONS, raise ValueError("unsupported region"); runs first, even for an empty cart Validate qty | Loop over all items; if any item["qty"] < 1, raise ValueError("invalid qty") Empty cart | If cart is empty, return the five keys all set to 0 Subtotal and eligible | subtotal = sum(price*qty) over all items; eligible = the same sum over items whose category is not "gift-card" Coupon discount | If coupon is None, use 0; else code = coupon.strip().upper(): SAVE10 uses _pct(eligible,10); FLAT500 gives 500 if eligible >= 3000 else 0; anything else raises ValueError("unknown coupon") Member discount | If member, use _pct(eligible - coupon_discount, 5), else 0; discount = coupon_discount + member_discount Shipping | 0 if member or subtotal - discount >= 5000, else SHIPPING_FEE[region] Tax | tax = _pct(eligible - discount + shipping, TAX_PERCENT[region]) Total and return | total = subtotal - discount + shipping + tax; return a dict with exactly the five int keys Tests | Add tests covering every row of section 12 (pytest or unittest), asserting both the exact dicts and the exact error messages

11. Worked examples

Every value below was computed by hand using the rules above. Use them as test fixtures.

EX-1: basic US order, no coupon, not a member

  • Cart: one item, price 1999, qty 2, category "books".
  • subtotal = 3998, eligible = 3998, discount = 0.
  • subtotal - discount = 3998 < 5000, so shipping = 599 (US).
  • taxable = 3998 - 0 + 599 = 4597. Tax at 7% is 321.79, which rounds to **322**.
  • total = 3998 - 0 + 599 + 322 = **4919**.
  • Result: `{subtotal: 3998, discount: 725?}` does not apply here; the result is `{subtotal: 3998, discount: 0, shipping: 599, tax: 322, total: 4919}`.

EX-2: EU, SAVE10, member, with a gift card

  • Cart: price 2500, qty 2, "apparel" (5000) and price 2000, qty 1, "gift-card" (2000).
  • subtotal = 7000, eligible = 5000.
  • SAVE10 = 10% of 5000 = 500. Member = 5% of (5000 - 500 = 4500) = 225. discount = 725.
  • Member, so shipping = 0. The threshold would also be met: 7000 - 725 = 6275.
  • taxable = 5000 - 725 + 0 = 4275. Tax at 20% = **855**.
  • total = 7000 - 725 + 0 + 855 = **7130**.
  • Result: `{subtotal: 7000, discount: 725, shipping: 0, tax: 855, total: 7130}`

EX-3: half-up rounding and coupon normalisation (UK)

  • Cart: price 1005, qty 1, "toys". coupon = " save10 ", member = False.
  • The code normalises to "SAVE10". 10% of 1005 = 100.5, which rounds half up to **101**. Note that `round()` would wrongly give 100.
  • subtotal - discount = 904 < 5000, so shipping = 899 (UK).
  • taxable = 1005 - 101 + 899 = 1803. Tax at 20% is 360.6, which rounds to **361**.
  • total = 1005 - 101 + 899 + 361 = **2164**.
  • Result: `{subtotal: 1005, discount: 101, shipping: 899, tax: 361, total: 2164}`

EX-4: FLAT500 below its minimum; gift card lifts shipping over the threshold (US)

  • Cart: price 2999, qty 1, "home" and price 5000, qty 1, "gift-card". coupon = "FLAT500".
  • subtotal = 7999, eligible = 2999. Since 2999 < 3000, the coupon gives **0** and does not raise. discount = 0.
  • subtotal - discount = 7999 >= 5000, so shipping = 0.
  • taxable = 2999. Tax at 7% is 209.93, which rounds to **210**.
  • total = 7999 + 0 + 210 = **8209**.
  • Result: `{subtotal: 7999, discount: 0, shipping: 0, tax: 210, total: 8209}`

EX-5: FLAT500 at exactly 3000 plus member (US)

  • Cart: price 1500, qty 2, "home". coupon = "flat500", member = True.
  • eligible = 3000 >= 3000, so the coupon = 500. Member = 5% of 2500 = 125. discount = 625.
  • Member, so shipping = 0.
  • taxable = 3000 - 625 = 2375. Tax at 7% is 166.25, which rounds to **166**.
  • total = 3000 - 625 + 0 + 166 = **2541**.
  • Result: `{subtotal: 3000, discount: 625, shipping: 0, tax: 166, total: 2541}`

EX-6: member discount rounds half up (US)

  • Cart: price 1010, qty 1, "home". No coupon, member = True.
  • Member = 5% of 1010 = 50.5, which rounds to **51**. discount = 51. shipping = 0.
  • taxable = 959. Tax at 7% is 67.13, which rounds to **67**.
  • total = 1010 - 51 + 0 + 67 = **1026**.
  • Result: `{subtotal: 1010, discount: 51, shipping: 0, tax: 67, total: 1026}`

EX-7: free-shipping boundary (EU, not a member)

  • EX-7a, price 5000, qty 1: 5000 >= 5000, so shipping = 0. Tax = 20% of 5000 = 1000. Result: `{subtotal: 5000, discount: 0, shipping: 0, tax: 1000, total: 6000}`
  • EX-7b, price 4999, qty 1: 4999 < 5000, so shipping = 899. taxable = 5898. Tax is 1179.6, which rounds to 1180. Result: `{subtotal: 4999, discount: 0, shipping: 899, tax: 1180, total: 7078}`

EX-8: gift cards only (UK, not a member)

  • Cart: price 2000, qty 1, "gift-card". subtotal = 2000, eligible = 0, discount = 0.
  • 2000 < 5000, so shipping = 899. taxable = 0 - 0 + 899 = 899. Tax is 179.8, which rounds to **180** (the shipping is taxed).
  • total = 2000 + 899 + 180 = **3079**.
  • Result: `{subtotal: 2000, discount: 0, shipping: 899, tax: 180, total: 3079}`
Disregard the stray "discount: 725?" fragment in the EX-1 result line. The correct EX-1 result is `{subtotal: 3998, discount: 0, shipping: 599, tax: 322, total: 4919}`.
