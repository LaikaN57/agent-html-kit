Implementation Plan — pricing.quote()

A complete specification for a Python module pricing.py exposing one function that prices a shopping cart: subtotal, discounts (coupon + membership), shipping, tax and total. Everything an implementer needs is on this page; the original requirements are not needed.

Language: Python 3 Money: integer cents only Rounding: half up, per computation Regions: US · EU · UK

1Function contract

# pricing.py
def quote(cart, region, coupon=None, member=False) -> dict

Inputs

A dict with exactly these five keys, every value a Python int (cents). No other keys.

2Terms used in this plan

TermDefinition
gift cardAn item whose category equals "gift-card" exactly. Counts toward subtotal; never discounted; never taxed.
subtotalΣ price × qty over all items.
eligibleΣ price × qty over all items that are not gift cards. Coupons, member discount and tax operate on this amount.
coupon_discountDiscount produced by the coupon (0 if no coupon or coupon condition not met).
member_discount5 % of (eligible − coupon_discount), only if member is true; else 0.
discountcoupon_discount + member_discount. This is the value returned under "discount".
half upRound to the nearest whole cent; an exact .5 goes up (100.5 → 101, 50.5 → 51). Python's built-in round() uses banker's rounding (100.5 → 100) and must not be used.
pct(amount, p)Shorthand in this plan for "p percent of amount, rounded half up to a whole cent". For non-negative integer amounts: (amount * p + 50) // 100 — pure integer arithmetic, no floats.

4.7 Rounding

Do not use round() or floats. round(100.5) == 100 and round(50.5) == 50 in Python (banker's rounding); the spec requires 101 and 51. Floats can also mis-represent values like x.xx5. Use (a * p + 50) // 100, valid because every base is a non-negative integer (see D4). decimal.Decimal with ROUND_HALF_UP is an acceptable alternative but the integer formula is preferred.

4.8 Total

total = subtotal − discount + shipping + tax (no further rounding).

5Decisions on gaps in the requirements

The requirements are silent on these points. Implement as stated below; items marked confirm should be confirmed with the product manager but must not block implementation.

#QuestionDecision
D1When is an unknown coupon detected — during validation or only when applying the coupon? (Matters for an empty cart with a bad code.)During validation, as step V3 after region and qty, before the empty-cart shortcut. So quote([], "US", coupon="BAD") raises unknown coupon. Rationale: bad input should never silently succeed.confirm
D2Is region case-insensitive like coupons?No. Only coupons are normalised. "us" → unsupported region.final
D3Is the empty string a "no coupon"?No. Only None means no coupon. "" and " " → unknown coupon.final
D4Negative or zero prices?Not validated (no rule given; do not invent new errors). The plan assumes price ≥ 0, which keeps every rounding base non-negative.confirm
D5Is the "gift-card" match case-sensitive?Yes, exact string equality.final
D6Type checking of inputs (e.g. qty as float, missing keys)?Not required; no extra validation or error messages beyond the three defined. Missing keys may raise KeyError naturally.final
D7Side effectsMust not mutate cart or its items. Pure function, no I/O, no global state.final
D8Can discount exceed eligible?No, by construction: FLAT500 only applies when eligible ≥ 3000 > 500; SAVE10 + 5 % are fractions. No clamping logic needed.final
D9member typeUse plain truthiness (if member:).final

6Ordered implementation steps

0 of 9 steps done
    • SHIPPING_RATES = {"US": 599, "EU": 899, "UK": 899}
    • TAX_PERCENT = {"US": 7, "EU": 20, "UK": 20} (the key set doubles as the supported-region set)
    • FREE_SHIPPING_THRESHOLD = 5000, FLAT500_MINIMUM = 3000, FLAT500_AMOUNT = 500, SAVE10_PERCENT = 10, MEMBER_PERCENT = 5, GIFT_CARD = "gift-card"
    • _pct(amount: int, percent: int) -> int returning (amount * percent + 50) // 100.
    • Unit-test it alone: _pct(1005,10)=101, _pct(1010,5)=51, _pct(1004,10)=100, _pct(0,20)=0, _pct(899,20)=180.
    • if region not in TAX_PERCENT: raise ValueError("unsupported region") — first statement of quote.
    • Loop all items; if any item["qty"] < 1 raise ValueError("invalid qty").
    • If coupon is None: code = None. Else code = coupon.strip().upper(); if not in {"SAVE10", "FLAT500"} raise ValueError("unknown coupon").
    • If not cart: return the five keys all 0.
    • subtotal over all items; eligible over items with category != "gift-card".
    • coupon_discount per table 4.3 (rounded at once for SAVE10).
    • member_discount = _pct(eligible - coupon_discount, 5) if member else 0.
    • discount = coupon_discount + member_discount.
    • Shipping per table 4.5 (member → 0; subtotal - discount >= 5000 → 0; else region rate).
    • tax = _pct(eligible - discount + shipping, TAX_PERCENT[region]).
    • total = subtotal - discount + shipping + tax.
    • Return a new dict with exactly subtotal, discount, shipping, tax, total, all int.
    • Every worked example in section 7 as a parametrised test; assert the whole returned dict with == (catches extra keys) and type(v) is int for each value.
    • Error tests assert both exception type and exact message (pytest.raises(ValueError, match=r"^unknown coupon$")).

9Pitfalls checklist

Using round() or /. / produces floats and round() is banker's rounding. Only (a * p + 50) // 100.
Rounding once at the end. Each percentage is rounded the moment it is computed; the member discount is based on the already-rounded SAVE10 value, and tax on the already-rounded discount.
Mixing up subtotal and eligible. FLAT500 threshold, SAVE10, member discount and tax base use eligible; the free-shipping threshold and total use subtotal.
Forgetting to tax shipping. Tax base is eligible − discount + shipping.
Checking the empty cart before validation. quote([], "XX") must still raise.
Treating "" as no coupon, or normalising region.
Shipping strict vs non-strict. Free when subtotal − discount >= 5000 (5000 itself is free); FLAT500 when eligible >= 3000 (3000 itself qualifies).
