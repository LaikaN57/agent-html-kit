# pricing.py: `quote()` Implementation Plan

stats: 1 function | 5 output keys | 3 regions | 2 coupon codes | 3 error messages | 0 floats

> Note: This plan is the only spec. Every rule, number, error message and edge case from the product requirements is restated here. Where the requirements were ambiguous, the plan states a decision and lists it under **Open questions**.

## 1. Scope

Create a Python module `pricing.py` with one public function:

```python
quote(cart, region, coupon=None, member=False) -> dict
```

| Parameter | Type | Meaning |
|---|---|---|
| `cart` | `list[dict]` | Line items. May be empty. |
| `region` | `str` | Must be exactly `"US"`, `"EU"` or `"UK"`. |
| `coupon` | `str` or `None` | Optional coupon code. `None` means no coupon. |
| `member` | `bool` | Whether the customer is a member. Defaults to `False`. |

Each cart item is a dict with these keys:

| Key | Type | Meaning |
|---|---|---|
| `sku` | `str` | Identifier. Not used in calculations. |
| `price` | `int` | Unit price in **cents**. |
| `qty` | `int` | Quantity. Must be ≥ 1. |
| `category` | `str` | `"gift-card"` gets special treatment. All other values are treated the same. |

**Return value:** a dict with **exactly** these five keys, all `int` cents:

| Key | Meaning |
|---|---|
| `subtotal` | Sum of `price * qty` over all items, gift cards included |
| `discount` | Coupon discount + member discount |
| `shipping` | Shipping charge |
| `tax` | Tax charge |
| `total` | `subtotal - discount + shipping + tax` |

All money is integer cents on input and output. **Do not use floats anywhere** (see Rounding).

## 2. Calculation flow

```diagram
title: quote() calculation flow
Caller [user] -> Validate region: cart, region, coupon, member
Validate region -> Error unsupported region [ext]: region not US/EU/UK
Validate region -> Validate qty: ok
Validate qty -> Error invalid qty [ext]: any qty < 1
Validate qty -> Empty cart check: ok
Empty cart check -> Zero result: cart == []
Empty cart check -> Subtotal and eligible: cart has items
Subtotal and eligible -> Coupon discount: eligible = non-gift-card subtotal
Coupon discount -> Error unknown coupon [ext]: unrecognised code
Coupon discount -> Member discount: coupon_disc
Member discount -> Shipping: discount = coupon_disc + member_disc
Shipping -> Tax: shipping
Tax -> Total: tax
Total -> Caller [user]: dict of 5 ints
```

## 3. Rules

### 3.1 Validation (runs first, in this order)

| # | Check | Condition that fails | Raise |
|---|---|---|---|
| V1 | Region | `region` not in `{"US", "EU", "UK"}`. Exact, case-sensitive match. | `ValueError("unsupported region")` |
| V2 | Quantity | Any item, including gift cards, has `qty < 1` (0 or negative) | `ValueError("invalid qty")` |

- V1 runs before V2. If both fail, raise `"unsupported region"`.
- Validation runs **before** the empty-cart shortcut. An empty cart with a bad region still raises.
- Error messages must match the strings above exactly, with no extra text.

### 3.2 Empty cart

After validation passes, if `cart` is empty, return:

```python
{"subtotal": 0, "discount": 0, "shipping": 0, "tax": 0, "total": 0}
```

This applies regardless of `coupon` or `member`. No shipping is charged.

### 3.3 Subtotal and eligible amount

| Value | Formula |
|---|---|
| `subtotal` | Σ `price * qty` over **all** items |
| `eligible` | Σ `price * qty` over items whose `category != "gift-card"` |

Gift cards count toward `subtotal` and toward the free-shipping threshold. They are **never discounted and never taxed**. They are excluded from `eligible`, and `eligible` is the base for all discounts and tax.

### 3.4 Coupon

Normalise the code with `coupon.strip().upper()`. Then:

| Normalised code | Condition | `coupon_disc` |
|---|---|---|
| *(coupon is `None`)* | none | `0` |
| `SAVE10` | always | `pct(eligible, 10)`, i.e. 10% rounded half up |
| `FLAT500` | `eligible >= 3000` | `500` |
| `FLAT500` | `eligible < 3000` | `0`, with no error |
| anything else, including `""` and whitespace-only | none | raise `ValueError("unknown coupon")` |

`FLAT500` cannot make the discount exceed `eligible`, because it only applies when `eligible >= 3000`.

### 3.5 Member discount

| `member` | `member_disc` |
|---|---|
| `True` | `pct(eligible - coupon_disc, 5)`, i.e. 5% rounded half up, applied **after** the coupon |
| `False` | `0` |

`discount = coupon_disc + member_disc`

### 3.6 Shipping

Evaluate top to bottom. The first matching row wins.

| # | Condition | `shipping` |
|---|---|---|
| S1 | `member` is `True` | `0` |
| S2 | `subtotal - discount >= 5000` (uses `subtotal`, so gift cards count) | `0` |
| S3 | `region == "US"` | `599` |
| S4 | `region == "EU"` or `"UK"` | `899` |

The threshold is inclusive: exactly 5000 ships free.

### 3.7 Tax

```
tax_base = eligible - discount + shipping
tax      = pct(tax_base, rate)
```

| Region | Rate | Shipping fee (non-free) |
|---|---|---|
| US | 7% | 599 |
| EU | 20% | 899 |
| UK | 20% | 899 |

```chart
title: Tax rate by region
type: bar
unit: %
US: 7
EU: 20
UK: 20
```

Shipping **is** taxed. A cart with only gift cards therefore still pays tax on shipping when shipping is not free.

### 3.8 Total

```
total = subtotal - discount + shipping + tax
```

### 3.9 Rounding (half up, integer-only)

Each percentage result is rounded half up to a whole cent **at the moment it is computed**. That covers three values: the SAVE10 discount, the member discount and the tax. Never round an intermediate total twice, and never defer rounding.

> Warning: Python's built-in `round()` uses banker's rounding (`round(100.5) == 100`). Do **not** use it. Do not use floats either, because `0.07 * x` has binary-representation errors.

Implement a private helper using integer arithmetic only:

```
pct(amount, percent) = (amount * percent + 50) // 100
```

This is correct for `amount >= 0`. All bases are non-negative here, since `eligible - discount >= 0` and shipping is ≥ 0.

| Call | Exact value | `pct` result | `round()` would give |
|---|---|---|---|
| `pct(1005, 10)` | 100.5 | **101** | 100 ✗ |
| `pct(1010, 5)` | 50.5 | **51** | 50 ✗ |
| `pct(50, 7)` | 3.5 | **4** | 4 |
| `pct(2599, 7)` | 181.93 | **182** | 182 |
| `pct(899, 20)` | 179.8 | **180** | 180 |

## 4. Implementation steps

```steps
Create module | New file pricing.py. Module constants: REGIONS = {"US","EU","UK"}, TAX_RATE = {"US":7,"EU":20,"UK":20} (integer percent), SHIPPING_FEE = {"US":599,"EU":899,"UK":899}, FREE_SHIPPING_THRESHOLD = 5000, FLAT500_MIN = 3000, GIFT_CARD = "gift-card"
Add rounding helper | Private _pct(amount, percent) returning (amount * percent + 50) // 100. Integer only, no floats, no round()
Validate region | If region not in REGIONS raise ValueError("unsupported region"). This is the first statement of quote()
Validate quantities | Loop over all items. If any item["qty"] < 1 raise ValueError("invalid qty")
Empty-cart shortcut | If not cart, return the five keys all set to 0
Compute subtotal and eligible | subtotal = sum(price*qty) over all items. eligible = same sum excluding category == "gift-card"
Compute coupon discount | If coupon is None then 0. Else code = coupon.strip().upper(). SAVE10 gives _pct(eligible,10). FLAT500 gives 500 if eligible >= 3000 else 0. Anything else raises ValueError("unknown coupon")
Compute member discount | If member then _pct(eligible - coupon_disc, 5), else 0. discount = coupon_disc + member_disc
Compute shipping | 0 if member. Else 0 if subtotal - discount >= 5000. Else SHIPPING_FEE[region]
Compute tax | tax = _pct(eligible - discount + shipping, TAX_RATE[region])
Compute total and return | total = subtotal - discount + shipping + tax. Return dict with exactly subtotal, discount, shipping, tax, total
Write tests | Cover every worked example in section 5 and every error case in section 6 (pytest)
```

## 6. Error cases

| Input | Expected |
|---|---|
| region `"CA"` | `ValueError("unsupported region")` |

| coupon `"BOGUS"` with an empty cart | Returns all zeros (see open questions) |

## 8. Open questions (decisions taken; confirm with PM)

> Risk: An unknown coupon on an **empty cart** returns zeros under this plan. The requirements list only the region and qty checks as up-front validation, and the empty-cart shortcut comes before the coupon step. If the PM wants coupons validated up front, move the coupon-code check to just after V2.

| Question | Decision in this plan | Status |
|---|---|---|
| Unknown coupon on an empty cart | Returns zeros, no error | [warn] |
| Region case sensitivity | Exact match only. `"us"` raises. | [warn] |
| Empty or whitespace-only coupon string | Treated as unknown and raises. Only `None` means "no coupon". | [warn] |
| Negative `price`, non-int types, missing keys | Not validated. Behaviour is undefined, so no extra checks are added. | [warn] |
| Category matching | `"gift-card"` is matched exactly and case-sensitively | [warn] |

> OK: Discount can never exceed `eligible` (SAVE10 ≤ 10%, FLAT500 only when eligible ≥ 3000, member 5% of the remainder). So `tax_base` is always ≥ 0, and floor-based half-up rounding is safe.
