1. Scope and contract

Create a Python module pricing.py that exposes exactly one public function:

quote(cart, region, coupon=None, member=False) -> dict

  • cart: a list of items. Each item is a dict with keys "sku" (str), "price" (int, cents, per unit), "qty" (int) and "category" (str).
  • region: str. Must be one of "US", "EU", "UK".
  • coupon: None (no coupon) or a str code.
  • member: bool. Defaults to False.
  • Return value: a dict with exactly five keys, all Python int: subtotal, discount, shipping, tax, total. Do not add other keys.
Inputs and outputs are integer cents. Do not use floats anywhere in the calculation, and do not use Python's built-in round(): it rounds half to even (banker's rounding), which the requirements explicitly reject. Every value in the returned dict must be an int, not a float or Decimal.

2. Calculation flow

Caller [user] -> Validate region: cart, region, coupon, member Validate region [svc] -> Validate qty: region in US/EU/UK Validate region [svc] -> ValueError [ext]: "unsupported region" Validate qty [svc] -> Validate coupon: every qty >= 1 Validate qty [svc] -> ValueError [ext]: "invalid qty" Validate coupon [svc] -> Empty cart check: code is None, SAVE10 or FLAT500 Validate coupon [svc] -> ValueError [ext]: "unknown coupon" Empty cart check [svc] -> Zero result [db]: cart == [] returns all 0 Empty cart check [svc] -> Subtotals: cart has items Subtotals [svc] -> Coupon discount: subtotal, eligible Coupon discount [svc] -> Member discount: coupon_discount Member discount [svc] -> Shipping: discount = coupon + member Shipping [svc] -> Tax: shipping Tax [svc] -> Result [db]: total = subtotal - discount + shipping + tax

3. Rules

3.1 Validation (runs before anything else)

Run the checks in this exact order. The first failing check raises and nothing else runs. Error messages must match character for character.

Order | Check | Condition that fails | Raise 1 | Region | region is not exactly one of "US", "EU", "UK" | ValueError("unsupported region") 2 | Quantity | any item in the cart has qty < 1 (0 or negative) | ValueError("invalid qty") 3 | Coupon | coupon is not None and its normalized form is not SAVE10 or FLAT500 | ValueError("unknown coupon")
  • Region matching is exact and case-sensitive: "us" or " US" raises "unsupported region". (Only coupon codes are case-insensitive.)
  • If both region and qty are invalid, the error is "unsupported region", because region is checked first.
  • Validation runs even for an empty cart. An empty cart with a bad region still raises.
The requirements list region and qty under "validation comes first" and describe the unknown-coupon error in the coupon section. This plan treats the coupon check as part of validation (step 3, before the empty-cart shortcut). As a result, quote([], "US", "BOGUS") raises "unknown coupon" instead of returning zeros. The coupon is also checked when the coupon gives nothing (for example, FLAT500 below threshold is valid; an unknown code is always an error). [warn] Confirm with the PM. If they disagree, move check 3 after the empty-cart shortcut.

3.2 Empty cart

If all validation passes and cart is empty, return {"subtotal": 0, "discount": 0, "shipping": 0, "tax": 0, "total": 0}. No shipping is charged on an empty cart.

3.3 Subtotal and eligible amount

Value | Formula | Notes line amount | price * qty | per item subtotal | sum of line amounts over all items | includes gift cards eligible | sum of line amounts over items whose category != "gift-card" | gift cards are never discounted and never taxed

The category match is exact: only the string "gift-card" counts as a gift card.

3.4 Coupons

Normalize the code with coupon.strip().upper(). Examples: " save10 " becomes SAVE10, and "Flat500" becomes FLAT500. A non-None string that is empty or only whitespace normalizes to "" and raises "unknown coupon".

Normalized code | coupon_discount | Condition (coupon is None) | 0 | no coupon SAVE10 | half_up_pct(eligible, 10) | always applies; 0 if eligible is 0 FLAT500 | 500 | only when eligible >= 3000 FLAT500 | 0 | when eligible < 3000; this is not an error anything else | n/a | raise ValueError("unknown coupon") (during validation)

3.5 Member discount

member | member_discount False | 0 True | half_up_pct(eligible - coupon_discount, 5)

The member discount is applied after the coupon, on what remains of the eligible amount. Then:

discount = coupon_discount + member_discount (this is the value returned under "discount").

3.6 Shipping

Evaluate the rows top to bottom; the first match wins.

Rule | Condition | shipping 1 | member is True | 0 2 | subtotal - discount >= 5000 | 0 3 | region is US | 599 4 | region is EU or UK | 899

The free-shipping threshold uses subtotal (gift cards included) minus discount, not the eligible amount. Exactly 5000 qualifies.

3.7 Tax

Region | Rate US | 7% EU | 20% UK | 20%

tax_base = eligible - discount + shipping

tax = half_up_pct(tax_base, rate)

Gift cards are excluded from the tax base, but shipping is included. A cart that holds only gift cards and pays shipping is therefore still taxed on the shipping.

3.8 Total

total = subtotal - discount + shipping + tax

3.9 Rounding: half up at the moment of computation

Each of the three percentage results (the SAVE10 discount, the member discount and the tax) is rounded to a whole cent as soon as it is computed. Later steps use the rounded value. Do not carry fractional cents forward.

Implement a private helper _half_up_pct(amount, pct) using integer math only: (amount * pct + 50) // 100.

  • This formula is correct for amount >= 0. Every amount passed to it is non-negative: eligible >= 0; eligible - coupon_discount >= 0, because FLAT500 only applies when eligible is at least 3000 and SAVE10 takes 10%; and the tax base is non-negative for the same reason. Prices are assumed to be non-negative; the requirements define no validation for price.
  • Examples: 10% of 1005 = 100.5 → 101 (Python round would give 100). 7% of 750 = 52.5 → 53 (round gives 52). 5% of 4410 = 220.5 → 221 (round gives 220).

4. Implementation steps

Module constants | Define REGIONS = {"US","EU","UK"}, SHIPPING = {"US":599,"EU":899,"UK":899}, TAX_PCT = {"US":7,"EU":20,"UK":20}, FREE_SHIPPING_MIN = 5000, FLAT500_MIN = 3000, GIFT_CARD = "gift-card" Rounding helper | _half_up_pct(amount, pct) -> int returning (amount * pct + 50) // 100; integers only, no round(), no floats Validate region | if region not in REGIONS: raise ValueError("unsupported region") Validate qty | loop all items; if item["qty"] < 1: raise ValueError("invalid qty") Normalize and validate coupon | code = None if coupon is None else coupon.strip().upper(); if code not in (None, "SAVE10", "FLAT500"): raise ValueError("unknown coupon") Empty cart shortcut | if not cart: return all five keys = 0 Subtotals | subtotal = sum(price*qty); eligible = same sum but skipping category == "gift-card" Coupon discount | SAVE10 -> _half_up_pct(eligible, 10); FLAT500 -> 500 if eligible >= 3000 else 0; None -> 0 Member discount | member_discount = _half_up_pct(eligible - coupon_discount, 5) if member else 0; discount = coupon_discount + member_discount Shipping | 0 if member or subtotal - discount >= 5000, else SHIPPING[region] Tax | tax = _half_up_pct(eligible - discount + shipping, TAX_PCT[region]) Total and return | total = subtotal - discount + shipping + tax; return dict with exactly subtotal, discount, shipping, tax, total Tests | add the worked examples (section 5) and the edge cases (section 6) as unit tests, e.g. test_pricing.py with pytest
