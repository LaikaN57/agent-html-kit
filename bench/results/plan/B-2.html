Implementation Plan: pricing.quote()

Complete specification for a Python module pricing.py that prices a shopping cart. Everything needed to implement and test it is on this page. All money is integer cents.

1Function contract

# pricing.py
def quote(cart, region, coupon=None, member=False) -> dict

Inputs

A dict with exactly these five keys, every value a Python int (cents). No extra keys.

2Calculation flow

The order matters: validation first, then the empty-cart shortcut, then the money pipeline. Each percentage is rounded the moment it is computed.

3Business rules

3.1 Validation (runs before anything else)

#CheckFailureNotes
V1region is exactly "US", "EU" or "UK"ValueError("unsupported region")Exact, case-sensitive match. "us", " US", "CA" all fail. Checked first, so it wins over every other error, even on an empty cart.
V2Every item has qty >= 1ValueError("invalid qty")Checked after V1. qty of 0 or negative fails. Must be checked for all items before any money is computed.
V3Cart is empty— (not an error)Return {"subtotal":0,"discount":0,"shipping":0,"tax":0,"total":0}. No shipping is charged on an empty cart.

3.2 Subtotal and eligible amount

QuantityIncludes gift cards?Formula
subtotalyesΣ price × qty over all items
eligiblenoΣ price × qty over items whose category != "gift-card"

The gift-card check is an exact string comparison against "gift-card". Gift cards are never discounted and never taxed, which falls out naturally because both discounts and tax are computed from eligible, never from subtotal.

3.3 Coupons

Normalization: if coupon is None, there is no coupon. Otherwise code = coupon.strip().upper().

Normalized codeCoupon discount cCondition
(coupon is None)0—
SAVE10half_up(eligible × 10 / 100)Always applies (is 0 if eligible is 0).
FLAT500500Only if eligible >= 3000. Otherwise c = 0 (no error).
anything elseValueError("unknown coupon")

Accepted spellings include "save10", " Save10 ", "flat500\n". "SAVE 10" (inner space) is unknown.

3.4 Member discount

memberMember discount m
Truehalf_up((eligible − c) × 5 / 100)
False0

Applied after the coupon, on the eligible amount already reduced by the (already rounded) coupon discount. Returned discount = c + m.

3.5 Shipping

PriorityConditionshipping
1member is true0
2subtotal − discount >= 5000 (inclusive; subtotal includes gift cards)0
3otherwise, region US599
3otherwise, region EU or UK899
The free-shipping threshold uses subtotal (with gift cards) minus the full discount, not the eligible amount. A cart with a 5000-cent gift card ships free.

3.6 Tax

RegionRate
US7%
EU20%
UK20%
 
tax_base = eligible - discount + shipping
tax      = half_up(tax_base * rate_percent / 100)

Shipping is taxed. Gift cards are excluded because the base starts from eligible.

3.7 Total

total = subtotal - discount + shipping + tax

Uses subtotal (gift cards included), so gift-card value is charged but untaxed and undiscounted.

4Rounding

Exactly three values are percentages and must be rounded to a whole cent, half up, at the moment each is computed (never carry fractions forward):

ValuePercentOf
SAVE10 coupon discount10eligible
Member discount5eligible − c (c already rounded)
Tax7 or 20eligible − discount + shipping (discount already rounded)
Do not use round(). Python's round() rounds half to even: round(52.5) == 52, but half up requires 53. Do not use floats at all.

Required helper

Implement one private helper used for all three values, with integer-only arithmetic:

_pct_half_up(amount: int, percent: int) -> int
    # returns (amount * percent + 50) // 100

This is exact for amount >= 0, which always holds here given non-negative prices (all three bases are ≥ 0). Alternative with identical results: decimal.Decimal with ROUND_HALF_UP, quantized to Decimal("1"), converted back with int().

5Implementation steps

0 of 0 steps checked — click a step title to mark it done.

  1. Create module and constants
    Create pricing.py. Define module-level constants: tax percent per region {"US": 7, "EU": 20, "UK": 20}; shipping per region {"US": 599, "EU": 899, "UK": 899}; FREE_SHIPPING_THRESHOLD = 5000; FLAT500_MINIMUM = 3000; FLAT500_AMOUNT = 500; SAVE10_PERCENT = 10; MEMBER_PERCENT = 5; GIFT_CARD = "gift-card". The set of supported regions is the keys of the tax table.
  2. Write the rounding helper
    _pct_half_up(amount, percent) returning (amount * percent + 50) // 100. Integer-only. Unit-test it first against the table in §4, including 5250/100 → 53.
  3. Define the signature
    def quote(cart, region, coupon=None, member=False):. Do not mutate cart or its items.
  4. Validate region
    If region is not one of the three keys → raise ValueError("unsupported region"). This is the very first statement of logic.
  5. Validate quantities
    Loop all items; if any item["qty"] < 1 → raise ValueError("invalid qty"). Complete this loop before computing any money.
  6. Empty-cart shortcut
    If cart is empty, return the five keys all set to 0. Return before coupon parsing (see §8, Q1).
  7. Compute subtotal and eligible
    One pass: add price * qty to subtotal for every item; also add it to eligible when category != "gift-card".
  8. Coupon discount
    If coupon is None: c = 0. Else normalize with .strip().upper(); "SAVE10" → c = _pct_half_up(eligible, 10); "FLAT500" → c = 500 if eligible >= 3000 else 0; else raise ValueError("unknown coupon").
  9. Member discount
    m = _pct_half_up(eligible - c, 5) if member else 0. Then discount = c + m.
  10. Shipping
    If member or subtotal - discount >= 5000 → shipping = 0; else the region's shipping constant.
  11. Tax
    tax = _pct_half_up(eligible - discount + shipping, TAX[region]).
  12. Total and return
    total = subtotal - discount + shipping + tax. Return a new dict with exactly the keys subtotal, discount, shipping, tax, total, all int.
  13. Tests
    Write one test per row of the test matrix (§7) and per worked example (§6). Assert full dict equality (catches extra keys) and type(v) is int for every value. For errors assert both type and exact message.

8Open questions & chosen defaults

The requirements leave these points unstated. Implement the default shown and keep the decision in one obvious place so it is easy to change if the product manager decides otherwise.

#QuestionDefault implemented
Q1Empty cart with an unknown coupon: error or zeros?Return zeros. The spec lists only region and qty under "validation", followed by the empty-cart rule; coupon handling comes afterwards.
Q2Should missing keys, non-int prices/qty, negative prices or non-str coupons be validated?No. Not specified; do not add checks or extra error messages. Rounding helper assumes non-negative bases.
Q3A cart of only gift cards still pays shipping and tax on shipping (Example H). Intended?Yes, follow the formula literally.
Q4Is region matching case-insensitive like coupons?No. Exact match only; "us" raises.
