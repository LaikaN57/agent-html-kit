4Walkthrough: one checkout

Step through a single checkout. The active step is highlighted in the diagram above; scroll up or use the mini view at right.

  1. Customer submits checkout
    The Web app (browser) or the Mobile app sends the checkout request to the API gateway over HTTPS.
  2. Gateway routes to Checkout
    The API gateway calls the Checkout service over gRPC.
  3. Load the cart
    The Checkout service loads the cart from the Cart service over gRPC. The Cart service keeps carts in Redis, the cart cache, which it reads and writes.
  4. Get a fraud score
    The Checkout service asks the Fraud service for a fraud score. The score must pass for the order to be written.
  5. Charge the card
    The Checkout service asks the Payment service to charge the card; the Payment service makes the payment API call to Stripe. The charge must succeed for the order to be written.
  6. Write the order gated
    Only once the fraud score has passed and the charge has succeeded, the Checkout service writes the order to Postgres.
  7. Announce the order
    The Checkout service publishes order.created to Kafka.
  8. Send the receipt
    The Email service consumes order.created from Kafka and sends the receipt.
Not specified in the source material Ask the team before assuming any of these:
  • Whether the fraud check happens before the charge, after it, or in parallel. Only the requirement that both pass before the order write is defined.
  • Whether order.created is published before or after the Postgres write.
  • What happens when the fraud score fails or the charge does not succeed, beyond the order not being written.
  • How the response travels back to the Web or Mobile app.
  • Protocols for connections other than the HTTPS and gRPC links listed.
