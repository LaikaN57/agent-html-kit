# Checkout Platform Architecture Overview

stats: 12 components | 11 connections | 1 external provider | 1 event topic

## Components

| Component | Role |
|---|---|
| Web app | Browser client |
| Mobile app | Mobile client |
| API gateway | Entry point for both clients |
| Checkout service | Orchestrates checkout |
| Cart service | Loads, reads and writes carts |
| Payment service | Charges the card |
| Fraud service | Returns a fraud score |
| Postgres | Orders database |
| Redis | Cart cache |
| Kafka | Event bus |
| Stripe | External payment provider |
| Email service | Sends receipts |

## System diagram

```diagram
title: Checkout platform
Web app [user] -> API gateway [svc]: HTTPS
Mobile app [user] -> API gateway [svc]: HTTPS
API gateway [svc] -> Checkout service [svc]: gRPC
Checkout service [svc] -> Cart service [svc]: gRPC, loads the cart
Cart service [svc] -> Redis [cache]: reads and writes carts
Checkout service [svc] -> Fraud service [svc]: asks for a fraud score
Checkout service [svc] -> Payment service [svc]: charges the card
Payment service [svc] -> Stripe [ext]: payment API call
Checkout service [svc] -> Postgres [db]: writes the order
Checkout service [svc] -> Kafka [queue]: publishes order.created
Kafka [queue] -> Email service [svc]: consumes order.created
```

> Note: An order is only written to Postgres after the fraud score passes and the charge succeeds.

## One checkout, step by step

```steps
Client request | The Web app or Mobile app calls the API gateway over HTTPS.
Route to checkout | The API gateway forwards the request to the Checkout service over gRPC.
Load the cart | The Checkout service loads the cart from the Cart service over gRPC; the Cart service reads it from Redis.
Fraud check | The Checkout service asks the Fraud service for a fraud score.
Charge the card | The Checkout service asks the Payment service to charge the card; the Payment service calls the Stripe payment API.
Write the order | Only if the fraud score passes and the charge succeeds, the Checkout service writes the order to Postgres.
Publish the event | The Checkout service publishes order.created to Kafka.
Send the receipt | The Email service consumes order.created from Kafka and sends the receipt.
```

> Warning: The source data defines only one ordering rule (the order is written after the fraud score passes and the charge succeeds). The rest of the step order above follows the listed connections and is not otherwise specified.
