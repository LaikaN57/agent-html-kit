Walkthrough: one checkout

Step through the request; the diagram above highlights the connections involved in each step.

Not started
  1. Customer checks out. The request leaves the Web app (browser) or the Mobile app and reaches the API gateway over HTTPS.
  2. Gateway hands off. The API gateway calls the Checkout service over gRPC.
  3. Cart is loaded. The Checkout service loads the cart from the Cart service over gRPC; the Cart service reads carts from Redis, the cart cache.
  4. Fraud check. The Checkout service asks the Fraud service for a fraud score.
  5. Card is charged. The Checkout service asks the Payment service to charge the card; the Payment service makes the payment API call to Stripe.
  6. Order is written — only if allowed. If, and only if, the fraud score passed and the charge succeeded, the Checkout service writes the order to Postgres.
  7. Event is published. The Checkout service publishes order.created to Kafka.
  8. Receipt is sent. The Email service consumes order.created from Kafka and sends the receipt.

Ordering note: the source material fixes one ordering constraint — the order write happens after both a passing fraud score and a successful charge. It does not specify whether the fraud check or the charge happens first, so steps 4 and 5 are listed in a readable order, not a guaranteed one.
